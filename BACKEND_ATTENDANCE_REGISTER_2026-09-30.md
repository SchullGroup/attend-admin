# Backend — two additions to the attendance register export (2026-09-30)

Two things the attendance register CSV needs for it to stand as an AGM record. Both are
server-side: the register is generated by
`GET /api/v1/client/events/{eventId}/post-agm/export/attendance`, and the frontend only downloads
whatever columns you return — so **nothing changes on our side, new columns appear automatically.**

## 1. Share units per attendee

Each row needs the attendee's **shareholding (share units)**.

For an AGM, attendance isn't a headcount — it's weighted by shares. Quorum is a share threshold,
and the register is the evidence for it, so a register without per-attendee share units can't be
reconciled against the quorum figure or the statutory return. The share totals are already in the
statutory return at the aggregate level; this is the same number, per person, on the register.

- Column: **Share Units** (the attendee's holding on this event's register).
- If a shareholder holds across multiple accounts/certificates that were consolidated, the figure
  should be their total for this register, matching how quorum was computed.

## 2. A real "attended" indicator, distinct from "registered"

Right now the register is described as "all registrants with check-in status." We need each row to
show clearly whether the person **actually attended the live event**, not just that they registered
or were on the list.

The distinction matters because registered ≠ attended, and for an AGM only actual attendance counts
toward quorum and toward the minutes ("X shareholders present or represented"). So each row needs:

- **Attended** — did they actually take part? Please define it by event format:
  - **In-person:** checked in (the QR/desk check-in you already record).
  - **Virtual / webinar:** actually joined the live session (Zoom join event), not merely RSVP'd.
  - **Hybrid:** either of the above.
- **Attendance mode** — In person / Online / Proxy / Did not attend — so the register itself shows
  how each present shareholder was counted. This lines up with the summary cards we already show
  (Present in Person, Present by Proxy) and lets the per-row register reconcile to those totals.
- **Proxy:** where a shareholder attended by proxy, the register should show that, and ideally the
  proxy holder's name, since "present or represented" in the minutes covers both.

If the Zoom join data is what determines virtual attendance, note that webinar attendance comes from
Zoom's participant report — happy to discuss where that hooks in, but it's your call on the source.

## Suggested column set

For reference, a register row that would support the statutory return and the minutes:

```
Name, Email, CHN, Share Units, KYC Status, Attendance Mode, Attended, Checked-in At, Proxy Holder
```

Order and exact headers are yours — the two must-haves are **Share Units** and a definitive
**Attended** (with the mode behind it). We render whatever you send, so once these are in the CSV
they show up in the export with no release on our side.

## Why it matters together

With share units and a real attended flag on each row, the attendance register, the quorum figure,
and the statutory return all reconcile from the same evidence — which is the point of the register
for a filing. Without them, the register shows who signed up, not who was actually present and how
much of the company they represented.
